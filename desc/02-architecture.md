# 技术方案

状态：候选方案，尚未实现｜更新：2026-11-06

## 数据流

```text
公开录像 + 时间同步 + 标定 + 平面图
  → 预训练人员检测 → 各摄像头独立跟踪
  → 地面位置映射 → 跨摄像头关联与重叠去重
  → 匿名轨迹 → 区域事件与点位语义
  → 热力图 / 路线 / 旅程 / 数据质量报告
```

候选：Ultralytics 预训练检测模型和 ByteTrack 为基线；对比 BoT-SORT；OpenCV 负责坐标变换；参考 MelMOT 的时空匹配，必要时使用许可合适的预训练 ReID。版本和权重在样本运行、速度及许可检查后固定。跟踪器的单镜头 ReID 不自动提供全局跨镜头身份。

## 数据契约草案

- `camera`：摄像头、时间偏移、覆盖范围、标定及其版本。
- `observation`：时间、摄像头、局部轨迹 ID、检测置信度、图像坐标、地面坐标及位置质量。
- `association`：局部轨迹对、关联方法、分数、状态及算法版本；低置信度保持未关联。
- `visit`：单次匿名到访 ID、起止时间、可见范围、轨迹完整性；中断不自动视为离店。
- `zone` / `point`：区域或点位 ID、类型、平面边界、布局版本及生效时间。
- `event`：访问 ID、事件类型、区域、时间、来源（观察 / 推断 / 模拟）、置信度及规则版本。

事件候选：`zone_entered`、`zone_exited`、`zone_dwelled`、`zone_transitioned`；模拟咨询与支付必须另标来源。进入和离开采用时间与距离滞回规则，减少边界抖动。停留按可观察时间计算，遮挡缺口单独记录。

## 指标口径

- 区域到达人数：指定时间内进入或被首次观察在区域的去重匿名访问数；分别说明后者。
- 经过热度：按人次或轨迹穿越计数，选择口径并显示；停留热度按可观察的人员时间累积。
- 路线：记录已观察区域顺序、关联状态与缺口；不可见区域不推测为已到达。
- 漏斗：注明按访问统计、有序或无序、时间窗口及样本量；不把到收银区当作支付。

## 质量与失败处理

分别报告检测、单镜头跟踪、跨镜头关联、地面定位和区域统计；参考标注的粒度和覆盖决定哪些指标可计算。报告重复计数、ID 合并/拆分、覆盖范围及未知比例。标定缺失、时间不同步、遮挡和低置信度应可见；禁止强行拼接。模拟数据和模型推断必须在界面和导出中标识。
