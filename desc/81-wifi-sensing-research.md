# Wi-Fi 感知与定位研究线

日期：2026-11-13。状态：调研和方案定义；尚未接入真实传感器，也没有实测定位结果。与多摄像头导入 MVP 并行，不替代该主线。

## 目标与区别

探索把 Wi-Fi 数据作为 WalkFlows 可选空间观测来源，最终在授权场所展示经过验证的区域存在或位置结果。图中 RuView 的方向是无须人员携带设备的 Wi-Fi 信道状态信息（CSI）感知；它与手机主动测距定位不同，也不天然产生可识别的人员身份或精确轨迹。默认不进行跨源身份关联，不把区域存在显示成个人位置。

## 项目调研

1. [RuView](https://github.com/ruvnet/RuView)：开源参考，其代码声明 MIT；模型权重、固件、依赖和数据集需分别核验许可。其[使用指南](https://github.com/ruvnet/RuView/blob/main/docs/user-guide.md)列出 ESP32 CSI、主机 RSSI 和模拟源。auto 可退回模拟，Docker 默认模拟；有画面不代表接到了真实 CSI。普通 Windows Wi-Fi 路径读取 RSSI，不能据此声称获取 CSI 或具备姿态定位能力。项目自身也说明实时姿态未达目标；[详细说明](https://github.com/ruvnet/RuView/blob/main/docs/readme-details.md)撤回了既往姿态精度数字，亦记录某存在检测结论撤回。应审视评估协议，不将宣传数字作为验收。
2. [乐鑫 esp-csi](https://github.com/espressif/esp-csi)：官方 CSI 采集参考，包含开发板之间与路由器通信的示例，以及带现场训练的存在和运动检测示例。芯片型号、驱动、天线、路由器配置和部署环境都会影响可用性；应根据现有硬件验证，而非假设任意网卡可用。
3. [Android Wi-Fi RTT](https://developer.android.com/develop/connectivity/wifi/wifi-rtt)：另一条用户设备主动参与的路线。支持的手机和接入点可测距，通常需要至少三个接入点及多边测量才能估计设备位置，并需要设备授权；这不是 RuView 式无设备人体感知，也不是自动追踪所有顾客。实际误差需现场验证。

## 推荐路线及取舍

优先研究 CSI 区域存在和运动：数据来源与硬件状态明确、能复现再逐步评估空间定位。先独立验证，不把视频检测器的输出当作 Wi-Fi 独立定位真值。手机 RTT 保留为需用户主动参与的独立适配器；RSSI 仅用于信号诊断和明确标识的粗粒度实验。短期不承诺无设备多人的连续轨迹、身份或生命体征。

## 预期接入契约

各适配器提供版本化观测：来源类型、真实/模拟、设备或数据集标识、采样时间和时钟偏差、场地坐标系与标定版本、能力类型（存在/区域/位置）、结果及不确定性、模型版本和健康状态。无法定位时位置为空；断连、模拟和不支持须明确呈现，不能产生伪轨迹。原始数据默认最小化保存；采集和关联仅在授权场景进行。Wi-Fi 和视频可共享场地坐标及时间轴，只有经过校准与独立评估才能融合，不能默认同一身份。

## 分阶段验收

- 研究阶段：确认真实支持的 CSI 设备、固件、协议、来源许可证和项目版本，记录环境及复现命令。
- 离线阶段：选择具有明确许可和对应标注的公开 CSI 数据，建立只读回放与来源标记；合成数据仅用于接口测试。存在、区域定位和人体姿态需分别评估，手势数据不能冒充定位真值。
- 硬件阶段：已有硬件可用时记录节点坐标、拓扑、采样、空场和有人对照；检查断流、时钟偏差及环境变化，不默认修改用户路由器。
- 效果阶段：对存在检测报告误报、漏报和延迟；对具备地面真值的定位报告误差分布、覆盖率及多人/遮挡/场景变化表现。与视频或人工标注交叉核验，但不得把融合结果与独立结果混淆。
- 产品阶段：展示来源、状态、能力、校准与可信度；只开放经真实场景验证的功能。
