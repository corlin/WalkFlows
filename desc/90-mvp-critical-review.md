# 当前项目批判性复核与 MVP 收敛

日期：2026-11-13。结论：项目已具备可复用的离线处理与研究复核组件，但尚不是普通操作员可以顺畅使用的完整产品；可用首版应聚焦“六路导入、人工时间和平面配置、本地处理、可追溯复核”，暂不承诺去重人数和业务级分析。当前验收主文件为 [多摄像头离线复核 MVP](79-multicamera-import-mvp.md)。这些建议保留 5–6 路和公共平面主目标，不把它降成固定样本播放器。

## 具体取舍

**保留并优先修通**：5–6 路视频输入、人工时间配置、真实坐标 / 映射、单镜轨迹、可视化共同平面、保守跨镜候选、来源导出、失败与无数据状态。首版输出面向人工复核，保留区域绘制作为辅助。

**后移并保留研究材料**：跨镜去重与连续身份、准确客流与停留、业务漏斗、模型训练 / 再训练、自动时空标定、实时流、Wi-Fi 硬件及融合。它们不是不重要，而是现有证据不足且会阻碍尽快交付受控可用首版。项目目标与之后阶段仍须分别验收。

**暂不声称**：任意六路输入均能可靠输出人员轨迹、无效投影代表零人、跨镜距离近即同一人、合成变帧率测试代表真实素材均可用，或某模型 / 阈值对所有门店最优。

## 下一步的最短闭环

1. 将导入 / 时间与标定 / 状态 / 结果串成一个清晰入口；保证 WSL 与 Windows 路径说明，修正文档中“生成新配置但仍运行旧配置”的问题。
2. 修复并回归测试单路不可播放不应静默阻断其他可用画面、元数据不符与无交集的状态；标记显示时间与视频时间的偏差，不承诺曝光同步。
3. 固定 site03 006、007 六路作为两组工作流验收，从新建项目开始保留实际交互证据、输入哈希、时长与失败项；site04 作为失败检查，不当作跨场景成功。项目是否支持用户自己的录像取决于编码、场景校准和检测覆盖，必须实际检验。
4. 人工可复核输出至少包括多镜同一时间的源画面、已标定平面点、局部 ID、候选距离及可导出的来源；所有未关联 / 无支持状态明确可见。通过后再邀请用户核验，不提前宣称整个业务愿景完成。
