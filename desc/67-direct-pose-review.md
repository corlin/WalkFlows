# Direct-pose research review

When the optional direct-pose experiment and its mixed hypotheses are present and pass provenance checks, the site03 page offers a fourth analysis source: direct-pose experiment. Selecting it updates the analysis track choices, plane trajectories, heatmaps, region candidates, transitions and funnel. Its export uses a distinct `experimental_direct_pose_not_validated_customer_counts` scope and records the hypothesis SHA-256.

The display explicitly states that camera-local baseline video boxes and local-observation quality rows remain based on the original baseline. The model-versus-reference comparison independently selects the baseline or direct-pose hypotheses and records its selected source and hash. Direct-pose hypothesis member IDs must not be confused with those baseline local box IDs. No experimental result is used as a verified identity or customer count.

The builder loads optional data only when the experiment report, hypotheses, baseline hash, reference, scene, per-camera input hashes, weights, video, sensor and producing scripts match. Missing or stale optional artifacts are omitted rather than silently displayed. To add the experiment, execute the commands in document 65, then run `.venv/bin/python -m walkflows prepare --cross-scene`; the normal preparation does not download the optional model or start its GPU experiment. No extra environment is needed.

Tests check source-specific export scope and reject missing provenance, and loader tests check missing and changed artifacts. Browser verification selected the direct-pose source and displayed eight hypotheses, 457 valid samples and four conflicts without changing the user's saved layout. These are research counts, not people.

The optional checkbox overlays the direct experiment's tracked boxes on the two video views as blue dashed `D ID` boxes, alongside the baseline boxes. It also shows the per-frame experimental box count and explicitly labels a camera without experimental output. These are detector/tracker boxes before the pose-geometry and duplicate filters, so not every displayed box becomes a floor hypothesis. The box IDs belong to the direct experiment and do not identify baseline local tracks or verified people. The bundle loader checks the source hash and validates frame, ID and box coordinates before exposing these boxes. Browser verification at frame 100 showed two experiment boxes on C0001056 and the missing-output message when a camera without direct-pose data was selected.

The model-versus-reference panel has an independent source selector; changing the main analysis source does not silently change this comparison. On the same example north/south layout and frames 0?398, browser verification showed baseline versus reference transitions of 0 versus 1, and direct-pose versus reference transitions of 1 versus 1. The selection and its SHA-256 are included in the research export; reference coverage and identity limitations remain unchanged. Testing used a separate localhost origin and its temporary example areas were removed afterwards.
