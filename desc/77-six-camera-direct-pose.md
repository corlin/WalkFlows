# Six-camera direct-pose coverage experiment

The existing site03 006 direct YOLO11s-pose tracking command accepts only C0001055_v4 and C0001056_v2, even though the scene has six calibrated cameras and the baseline uses all six. This limits evaluation of whether direct pose tracking adds useful cross-view coverage. The 006 scene has already influenced previous choices, so it is development evidence, not an independent blind validation.

Plan: extend the existing direct-pose command to the six cameras already present in its pinned source and calibration inventory, retaining confidence 0.1, 640 input, 0.5 ankle and reference radius and all existing verification. Recompute direct outputs for all six because the script hash changes. Add an explicit optional six-direct-camera research comparison with separate output; preserve the existing mixed two-direct-camera default and rebuild its artifacts after the source hash changes. Compare candidate coverage, conflicts, reference-near observations and event outputs without calling them identity accuracy, customer counts or verified business transitions. Require source-hash checks, meaningful tests for camera selection and default behavior, a full existing unit suite, and an end-to-end run. Do not promote automatically; use the independent site split and other clips for later validation.


## Result and reproducibility

The direct-pose command now accepts the six pinned cameras. All six 400-frame direct runs were recomputed using the existing pinned assets and GPU. The original two-direct-camera mixed comparison remains the default. The explicit --all-cameras option writes a separate data/processed/site03-direct-pose-all-journeys artifact and requires exactly the six unique site03 cameras. Both variants verify source hashes and conserve their eligible input observations.

In this same development clip, the original two-direct-camera mixed hypothesis set contains 681 input observations, 457 research-candidate hypothesis-frame samples, 4 spatial conflicts and 435 reference-near pairs. The six-direct-camera set contains 719 input observations, 473 research-candidate samples, 4 spatial conflicts and 450 reference-near pairs. The extra four cameras contributed 42, 0, 18 and 0 comparable eligible direct observations respectively for C0001020, C0001025, C0001029 and C0001053; the two original direct cameras yielded 239 and 420. Comparison uses a 0.5 scene-unit proximity gate, and observations are temporally correlated. Reference-near pairs do not prove person identity, recall or unbiased positioning accuracy. Different coverage and hypothesis association make this a whole-pipeline comparison rather than a controlled change in just one factor.

Under the unchanged illustrative north/south regions and existing event rules, the six-direct-camera hypotheses produce the same single north-to-south candidate at exit frame 100 and arrival frame 114 as the original mixed variant; no additional interrupted candidate appeared. These are not verified business events. The one-off event summary is saved as events-exploratory.json with its hypothesis hash and fixed region options; its wrapper is not yet a versioned command. The six-camera variant is research-only and has not been promoted as the default.

Rebuild by running scripts/probe_site03_pose_direct.py once for each of the six camera names with --camera, then scripts/evaluate_site03_direct_pose_journeys.py and scripts/evaluate_site03_direct_pose_journeys.py --all-cameras in the existing .venv. The standard site03 research verifier with --site03-only passed, including the Python suite and JavaScript tests. The optional all-camera report, its hypothesis hash, six input reports and per-frame coverage live under ignored data/processed paths. Next, test on a separate recording or reserved site without tuning on its reference; assess individual camera visibility, incorrect associations and region-event coverage before considering UI integration.


## Optional review integration

The site03 review now loads the six-camera direct artifact only when all six direct-camera inputs, model, video, calibration, reference, scripts and hypothesis hashes pass provenance checks. It appears as a separately labelled experimental trajectory source and comparison source. The blue direct-detection overlay follows the selected direct source; original local tracks and camera-quality rows remain baseline observations. Research JSON exports include the distinct six-camera source name and hypothesis hash. If the optional bundle is absent or stale, the six-camera option is omitted rather than silently substituting another source.

The normal mixed source and review default remain unchanged. On the prepared local page, selecting the six-camera source showed 473 valid research samples and four conflicts; switching to the mixed source showed 457 and four. The C0001020 direct overlay was present in six-camera mode and correctly reported unavailable for the mixed mode. A browser check also selected the six-camera comparison against a temporary example layout; test layout items were removed afterwards. The site03-only verifier passed with 121 Python tests and the JavaScript suite. These checks establish source selection and reproducibility, not physical identity or event correctness.
