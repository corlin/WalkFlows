# 多摄像头离线复核 MVP

状态：进行中｜更新：2026-11-13。本文件是当前 MVP 范围与验收的主入口；更早与本文件冲突的描述为历史记录。依据与取舍见 [项目现状批判性复核](90-mvp-critical-review.md)。

## 目标用户和可用结果

在 WSL2 的 `corlin` 用户与现有 `/home/corlin/WalkFlows/.venv` 中，一名熟悉录像和场地的操作员提供同一空间的 5–6 路本地视频，经过明确的时间及地面配置、本地处理，在浏览器查看多路画面、每镜人员框与局部轨迹、可用的平面投影，以及可人工复核的跨镜邻近候选。视频、轨迹和结论须能追溯输入与参数。

首版服务于**离线检查与人工复核**，不是可靠的自动客流统计产品。允许用户提供已有映射或手动对应点；没有空间标定时仍可使用单镜检测，平面和跨镜候选明确不可用。不能把同帧候选当成已确认身份、跨镜连续轨迹或去重人数。

“直接查看”指通过一个清晰的本地入口完成导入、配置、处理及复核，允许视频计算耗时和必要的人为校准；不承诺任意录像无需配置就自动识别或得到可靠人数。用户不应修改源码、复制固定数据集清单或逐相机手工执行一长串内部命令。

## 本期必须交付

1. **完整入口**：一个可发现的本地入口，支持指定 5–6 路 WSL 可访问的文件并命名，给出格式、时长、帧率、分辨率、验证或失败原因。Windows 路径须提供明确转换指引；可以使用清晰的命令启动本地页面，不要求公网或云端。
2. **时间配置与可回放性**：可查看并调整各路偏移及共同范围；无法播放、无交集、解码帧数不符或可疑变帧率必须提示并提供明确处理路径。支持的首版工作路径优先为可解码的恒帧率 H.264；其他编码或变帧率可使用已有预览与重采样工具，但不能声称重采样自动同步。需使用共同事件检查代表性时刻，不要求证明真实曝光同步。
3. **平面映射**：支持导入可用映射或逐镜选择不少于四个对应点并保存新配置；统一坐标原点、方向和单位。应能检查独立点、明确有效覆盖区与未标定状态。平面图非必需，可使用带单位的坐标平面；无真实底图时不能冒充现场平面。
4. **本地任务与结果**：显式启动处理，展示逐镜阶段、进度、失败与结束状态，避免重复后台任务；完成后能从明确入口打开结果。支持受条件约束的按相机安全续跑；输入、模型、参数和输出指纹可查。播放时可定位时间、选择或检查各路视频，展示局部框、编号及轨迹，并在标定有效时展示平面投影和邻近候选。浏览器播放或时间偏差不能静默冒充同步结果。
5. **可信的空值与复核**：显示各镜解码帧、观察和有效投影数量；无检测、无有效投影、无共同时间、文件损坏、无标定和歧义须区别展示，不能把零观察解释为零人。候选保留相机对、局部编号、时间、距离与未知 / 冲突状态。至少可导出带来源的观察或候选明细；区域绘制保留用于人工探索，事件与热度如显示必须标为候选和未去重。

## 本期不作为交付承诺

跨镜自动身份确认、跨镜完整轨迹及去重人数、客流 / 停留 / 区域流转的业务级准确统计、真实咨询与成交归因、漏斗、实时摄像头接入、Wi-Fi 定位、模型训练和泛化性能优化都移入后续阶段。现有研究功能可以保留，但不能作为 MVP 必须完成项或用来替代主流程验收。此取舍不删除这些方向，也不把未验证结果包装成成品功能。

## 验收：先证明工作流，再限定效果

- **两组输入**：在同一套本地环境，用已获取的 site03 006 和 007 两组不同六路录像，从新建项目开始独立完成时间配置、导入已有映射或对应点、处理及回放；记录路径和参数，禁止依赖写死的场景清单。它们同属一个场地，仅证明两组录像的工作流，不能证明跨场景泛化。
- **可操作性**：无需修改代码；从入口能找到下一步、任务状态和结果。验证每一路可解码、浏览器可用或明确报错；在开始、中间和结束附近抽查画面、时间、框与平面是否对应。截图或视频及准确操作步骤要留存，不以测试数量替代实际操作。
- **确有可复核输出**：在至少一组已知存在有效投影的样本上，展示有标定来源的多镜平面点和至少一组可追溯候选；通过视频与参考材料人工核查其来源，不要求因此宣称候选身份正确。第二组运行即使有失败，也必须如实记录，不能挑选一张成功画面作为全部效果。
- **失败路径**：自动测试及实际操作覆盖无标定、损坏或无法播放、无重叠、零检测或无有效投影、处理失败与受支持的续跑；错误不会被表示为零人、成功定位或已确认身份。逐镜完整解码与元数据不符须有清楚状态。
- **效果证据和边界**：保留检测、局部跟踪、投影、跨镜候选和区域事件各自的支持量及失败案例；参考数据不足时写明不可评估。用现有 site04 结果作为跨场景失败检查，而非宣称泛化已通过。质量门限在固定可见性、标注定义和实际用途后制定；不把关联候选数、相关帧数或临时 ID 当成准确率和人数。
- **资源与版本**：记录 WSL 用户、单一环境、视频和模型哈希、设备、运行耗时和主要依赖；启动的本地服务可停止，避免多份后台任务。项目代码、模型、依赖和数据的许可分别核验；仓库当前没有项目 LICENSE，开源发布前需明确授权。

## 执行顺序

1. 整理一个连贯入口和状态流，修复标定配置容易丢失、无法播放阻断全部视频、路径和诊断不清等主流程问题。
2. 完成两组固定六路输入的从零到回放验收，留存帧级 / 交互证据和失败项；先修实际阻塞，不为增加演示数字调阈值。
3. 确认目标范围内的可复核效果与限制后通知用户；真实跨场景、跨镜身份、业务指标、训练和 Wi-Fi 按独立里程碑推进。
