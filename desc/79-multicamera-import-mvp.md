# 下一阶段 MVP：导入多摄像头视频并展示结果

更新：2026-11-09。用户明确将此关键差距列为下一阶段 MVP 核心目标。本文是对既有产品目标与路线的推进，不意味着当前版本已经支持任意视频。

## 核心目标

在现有 WSL2 环境中，用户提供同一空间、不同视角的 5–6 段录像，经过明确的场景配置和本地处理后，在一个可访问的页面查看多路视频、匿名人员轨迹、共同平面上的跨镜候选及区域分析，并能追溯输入、参数和结果。重点是从用户的视频组到可交互结果的完整流程，而非只复现固定 site03 样本。

“直接展示”应理解为产品提供可操作的导入、配置、处理和查看流程；视频时长、GPU 性能以及配置是否完整会影响处理时间。不能承诺任何文件无需时间对齐、空间配置或计算即可得到可靠的跨镜身份和统计。

## 用户流程与输入

1. 创建一个场景或项目，选择或指定 5–6 个本地视频文件，并为每路设置可辨识的相机名称。界面显示文件有效性、视频格式、时长、帧率和分辨率；不将用户视频提交到 Git。
2. 配置公共时间轴：使用视频已有时间信息、用户提供的偏移，或在有可靠证据时给出可复核的估计；允许用户检查和调整，展示共同时间范围及无重叠或无法确定的情况。此处要求结果时间对齐，不把验证真实曝光同步设为所有录像的前置条件。
3. 配置公共空间：支持导入已有相机标定 / 投影参数，或提供用户可操作的平面对应点配置流程；明确坐标系、尺度和相机覆盖情况。必要时可使用用户提供的平面图或坐标网格，图像与坐标须可对应。不得把示例平面误认为真实场地。
4. 在用户启动后本地执行处理，展示分阶段进度、失败原因和可恢复状态；处理完成后自动或经明确入口打开结果。使用现有唯一项目虚拟环境与可用 GPU / CPU，不要求重新创建环境。
5. 页面支持选择和同步回放各摄像头，查看每路检测与局部轨迹、共同平面位置、跨镜关联候选、方向、区域及点位配置、热图和区域流转候选；显示来源、置信或不确定状态，并支持导出可追溯结果。

单摄像头检测和局部跟踪可在没有公共平面标定时运行与展示。缺少可用时间对齐或空间映射时，页面必须说明限制，保留尚未关联或未知状态；不得假装已生成可靠的共同平面轨迹或去重人数。候选关联与检测结果均不是已确认的真实身份。

## 可交付能力

- 通用视频组输入、文件和相机配置，处理多种常见本地视频格式；错误文件、缺失文件、不同帧率、时长差异、重复相机名称及中断需给出明确反馈。
- 与固定示例解耦的场景配置和处理入口；每次运行绑定文件指纹、时间偏移、标定 / 布局版本、模型、参数及输出版本，允许重复运行或安全复用有效缓存。
- 人员检测、单镜跟踪、质量过滤、平面投影和跨镜候选的端到端管线；遮挡、低置信度和冲突保留可追溯状态，不强行拼接身份。
- 可交互结果页：多路选择、时间定位、轨迹 / 方向叠加、平面展示、区域配置、热图、区域事件候选与导出；清楚区分实际观测、推断和模拟数据。
- 可观察的任务状态与资源管理：限制后台任务和子进程数量，支持失败定位及安全恢复；用户不应需要手工改源码或依赖固定数据集路径来完成流程。

## 验收条件

1. 在同一套已准备好的本地环境中，用一组 5–6 路同空间视频从创建场景开始，通过界面或清晰的命令入口完成配置、处理并打开结果；不得通过修改源代码或复用写死的 site03 清单实现。
2. 在第二组不同录像或场景上重复同一通用流程，验证它不是仅对单一固定样本有效。使用已有公开数据及其现有标定 / 标注时，明确数据来源、许可和验证范围；不要求新增录像采集或人工逐帧标注。
3. 对齐和标定配置、单路观察、多路平面候选、区域操作及结果导出均有端到端检查；错误输入、缺失标定、无重叠时间、无有效检测和任务中断有明确反馈，不出现虚构结果。
4. 结果与输入文件、处理参数、时间和空间配置、模型版本关联，重新运行可复核；参考数据存在时分别评估检测、局部跟踪、定位、跨镜关联及区域事件，报告覆盖和失败案例。阈值应依据可用真值、业务用途和目标硬件制定，不能用研究候选数量代替准确率或人数。
5. 界面在明显位置说明未经验证的身份和事件；不将咨询、成交或真实支付从视频位置推断出来。完成验收前保留现有研究模式和已知限制。

## 优先级与衔接

优先打通“视频组导入 → 时间 / 平面配置 → 通用本地处理 → 可回放结果”的主路径，再依据真实失败案例改善跨镜身份、遮挡处理、定位和事件质量。继续利用现有六路示例、完整公开数据和研究成果作为开发与对照；训练、验证和保留测试的隔离仍有效。用户此前要求的重要成果提交到远端 main，以及非 root、corlin 用户、单一 .venv 等协作约束继续适用。
