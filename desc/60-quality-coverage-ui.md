# Data coverage and quality in the local review

The site03 page now reports, for each camera and the active frame window, frames with and without local tracked observations, observation rows, rows admitted by the selected box/pose/hybrid projection and rows excluded by that projection. In pose mode it also retains ambiguous pose-match counts in the JSON report. Exclusion reasons may overlap; common reasons are shown in the page and all applicable reason counts are included in the research export. The summary also shows the selected analysis source's total track objects, in-window usable samples and spatial conflicts, plus the number of frames beyond published-reference coverage.

A frame with no tracked output is not proof that nobody was present, and observation rows are not people. Eligibility is an experimental geometry gate rather than verified localization, visibility, identity or detector recall. Model camera coverage is reported independently of whether the user selects published reference or experimental linked trajectories as the analysis source. Selecting a different analysis window or projection recomputes the view; the export stores the applied window and projection with the counts.

For the fixed full clip, the six cameras have 928 tracked observation rows; pose mode admits 549 rows. Two cameras have no tracked rows in all 400 frames, which is an observation gap rather than proof of no visible people. The published reference lacks the last video frame. A browser check confirmed switching to pose and selecting frames 100?200 updates the camera counts and removes that final-frame reference gap. Tests cover frame deduplication, multiple exclusion reasons, ambiguous/missing inputs, window boundaries and the real dataset totals.
